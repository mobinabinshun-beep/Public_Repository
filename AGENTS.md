# N.U repository instructions

This repository is part of the N.U project. Before adding or changing any project content:
1. Read the canonical [Cross-repository inventory-first and reuse-first protocol](https://github.com/mobinabinshun-beep/Repository/blob/main/Governance/NU-CROSS-REPOSITORY-INVENTORY-AND-REUSE-FIRST-PROTOCOL-fa.md).
2. Re-enumerate all repositories accessible to the project owner and inspect their relevant trees, branches, history, code, docs, tests, assets, manifests, workflows and interfaces.
3. Search Persian/English synonyms, acronyms, former names and behavior-equivalent implementations before creating anything new.
4. Prioritize reuse, extension, modular refactoring and integration; a parallel clone requires documented evidence that existing assets are absent or unsuitable.
5. Consolidate canonical goals, accepted decisions, dependencies and future vision before proposing new architecture.
6. Record repository inventory, read coverage, searches, existing assets, duplication/conflict map, reuse decision, vision alignment, tests and rollback.

If discovery is incomplete, mark the task BLOCKED — REPOSITORY DISCOVERY INCOMPLETE and continue read-only research only. Preserve owner authority and all applicable project governance.


## Mandatory explicit-scope anti-destruction lock
- This rule is mandatory for every AI model, coding agent, bot, script and contributor operating here. The latest direct user instruction is the strict authority for scope.
- Change only the named target and proven direct dependencies. Do not refactor, restyle, rename, migrate, optimize, upgrade, clean up or touch adjacent/unrequested features.
- Before writing, record exact in-scope paths, forbidden areas, baseline commit/checkpoint and minimum change budget. Inspect the proposed diff; remove every unrelated change.
- Preserve unrelated work and data. Never use whole-repository reset, force-push or broad rollback for a scoped request. Roll back only named paths from a verified checkpoint.
- If scope, ownership, dependency or recovery point is uncertain, stop before writing. Any unexpected diff or unrelated regression triggers stop and scoped recovery.
- Run focused tests; report exact files, checkpoint, machine results, deployment/read-back and human QA separately. Never claim technical branch protection unless verified in GitHub settings.
- For scoped tasks, this lock takes precedence over generic inventory-first wording that would widen work; inspect only directly relevant dependencies. Cross-repository discovery is required only when the user explicitly asks for cross-repository work or evidence proves a shared dependency.
